## 0. 한 줄 요약

> **서울에 처음 오는 한양대 신입생이, 학교에 와 보기 전에 3D 한양대 동네를 걸으며 기숙사·청년안심주택·자취방을 직접 들어가 보고, 첫 집이 "내 돈을 다 써버릴 놈"인지 계약 전에 숫자로 확인하는 서비스.**

조금 더 풀면:
- **보러 갈 수 없는 신입생**을 위해 — 3D로 동네를 걷고, 방 안까지 들어간다 (가족·친구와 같이 접속 가능)
- **시세를 모르는 신입생**을 위해 — 매물마다 적정 월세 대비 **초과액**을 보여준다 ("2년간 ○○○만 원을 써버릴 놈")
- **선택지를 모르는 신입생**을 위해 — 보고 있는 집을 근처 기숙사·청년안심주택과 같은 기준(환산 월세)으로 비교한다
- 입학 후에는 **내 집 기록**으로 지금까지 얼마나 더 냈는지 찾아낸다

## 1. 문제 정의

**신입생은 월세를 가장 비싸게 들어간다.**
- **동네를 모른다:** 지방·해외 출신은 입학 전 서울에 와서 방을 여러 번 보러 다니기 어렵다. 한 번 올라와서 하루 이틀 만에 결정한다.
- **시세를 모른다:** 비교 기준이 없어 "학교 도보 1분"에 웃돈을 낸다.
  - 한양대 인근 원룸 평균 월세 57.7만 → 64.2만 원 (+11.3%, 2026.02 보도), 관리비 5만 → 7.1만 원 (+42%, 2024 자료)
  - 같은 동네에서 "한양대 도보 1분" 11~14㎡ 원룸이 월 95~110만 원, 근처 다른 방은 월 31~48만 원 (2026.11 매물 확인)
- **선택지를 모른다:** 기숙사가 안에서 어떻게 생겼는지, 근처에 청년안심주택이 있는지 모른 채 자취방부터 계약한다.
- **혼자 정하지 않는다:** 부모님과 같이 결정하는데, 부모님도 현장을 못 본다.

## 3. 핵심 개념: 「초과액」 — 내 돈을 다 써버릴 놈 판정 (초안, 확정 아님)

여러 "혐의" 대신 **한 가지 숫자**로 판정한다. 아래 계산식과 기준값은 **초안**이며, 3-4의 고도화를 거쳐 확정한다.

### 3-1. 계산식 (초안)
1. **환산 월세** (보증금 차이를 없애고 비교하기 위해)
   `환산 월세 = 월세 + 관리비 + 보증금 × 전월세전환율 ÷ 12`
   - 전월세전환율: 공표된 지역 전환율 사용 (값·출처는 서버 담당이 확인 후 설정값으로 관리)
2. **적정 환산 월세**
   `적정 환산 월세 = (같은 동 · 비슷한 면적(±30%) · 최근 12개월 실거래의 ㎡당 환산 월세 중앙값) × 이 집 면적`
   - 표본이 10건 미만이면 인접 동까지 넓힘, 그래도 부족하면 "판정 보류"
3. **월 초과액** = 환산 월세 − 적정 환산 월세
4. **계약기간 총 초과액** = 월 초과액 × 계약 개월 수 (기본 24개월)
5. **초과율** = 월 초과액 ÷ 적정 환산 월세

### 3-2. 판정 등급 (초안)
| 초과율 | 등급 | 화면 문구 예 |
|---|---|---|
| ≤ +10% | 적정 | "시세대로예요" |
| +10 ~ +25% | 조금 비쌈 | "2년이면 ○○만 원 더 내요" |
| +25 ~ +50% | 비쌈 | "이 집이 내 돈을 써버릴 놈일 수 있어요" |
| > +50% | **범인** | "찾았다. 2년간 ○○○만 원을 써버릴 놈" |

> 2026-11-07 실거래 분포로 재조정 (3-4 "등급 기준값"): 처음 초안 5 / 15 / 30% 는 실제 계약된 거래의 11%가 범인이 되어 너무 엄격했다. 10 / 25 / 50% 에서는 적정 69% · 조금 비쌈 16% · 비쌈 10% · 범인 5%. 근거는 계약 문서 2-1장.

### 3-3. 함께 보여주는 숫자
- **내 예산 대비**: 사용자가 정한 월세·보증금 상한과 비교 (D9)
- **청년안심주택·기숙사와의 차이**: 근처 단지·기숙사 환산 월세와의 차이 × 24개월 (I19, N3)
- **과 건물까지 도보 시간**: 돈으로 환산하지 않고 분 단위로만 표시 (D5)

### 3-4. 고도화 후보 (장시현 검토 → 확정할 것)
| 항목 | 현재 초안 | 고도화 방향 |
|---|---|---|
| 전월세전환율 | 단일 지역 전환율 | 주택 유형(원룸·오피스텔)별 전환율, 출처·기준월 명시 |
| 관리비 | 표시된 관리비 그대로 합산 | 관리비에 포함된 항목(인터넷·수도 등) 차이를 보정 |
| 비교 기준(적정가) | 같은 동·면적 ±30% 중앙값 | 건물 유형(다가구·오피스텔), 준공 연도, 층(반지하·옥탑) 구분 |
| 옵션 | 반영 안 함 | 풀옵션 여부 등 가산·감산 검토 |
| 표본 부족 | 인접 동 확대 → 판정 보류 | 표본 수에 따라 "참고용" 신뢰도 표시 |
| 실거래 정제 | 그대로 사용 | 계약 취소·이상치 제거, 갱신 계약 구분 |
| 등급 기준값 | ~~5 / 15 / 30%~~ → **10 / 25 / 50%** (2026-11-07 재조정 완료) | 실거래 분포를 보고 재조정 |
| 검증 | 없음 | 실거래 일부를 떼어 오차 측정 (OKR 안 2 연계) |

## 5. 핵심 사용자 흐름

**흐름 1 — 집 찾기**
1. 학교 인증 → 학과 선택 → 예산 입력
2. 3D 공유 월드 입장, 초대 링크로 가족·친구 합류 가능
3. 건물 말풍선 색으로 초과 등급 확인 / 왼쪽 목록에서 필터 / 상단 검색
4. 마음에 드는 집은 **찜**
5. 집 선택 → 용의자 파일 (환산 월세, 적정가, 초과액, 도보 시간)
6. 실내 3D 입장
7. 판결 카드 → 근처 청년안심주택·기숙사와 비교
8. 찜 목록에서 후보끼리 다시 확인

**흐름 2 — 기숙사·청년안심주택**
1. [기숙사] 또는 [청년안심주택] 탭, 판결 카드의 비교 화면에서 진입
2. 3D에서 위치 확인 → 정보 카드 / 단지 상세
3. 호실·평면도 실내 입장 → 찜
4. (청년안심주택) 공고 캘린더 → 관심 단지 D-day 알림 등록

**흐름 3 — 양도**
1. (재학생) [양도] 탭 → 주소 입력 → 금액·기간·사진 입력 → 게시
2. (신입생) 양도 글 확인 → 자동 판정(환산 월세·초과액) → 3D로 건물·주변 보기 → 찜

**흐름 4 — 내 집 기록**
1. 내 집 등록 → 매달 월세·공과금 입력
2. 월간 리포트: 총 주거비, 지난달 대비, 적정가 대비 누적 초과액
3. 직접 설정한 계약 만료 알림 → 이사 결정 시 흐름 1, 남은 계약은 흐름 3(양도)

## 8. 기술 스택
- 프론트: Vite + React + TypeScript, React Three Fiber + drei, Rapier + ecctrl, 카카오맵 JS SDK
- 서버: Java 21 + Spring Boot 3 (Web, Data JPA, Security, Mail, Scheduler, **WebSocket**), springdoc-openapi
- DB: PostgreSQL + PostGIS
- 멀티플레이: Spring WebSocket 서버 1대, **공유 월드 1개**에 위치·이모트 브로드캐스트. 초대 링크는 초대한 사람 위치로 스폰. 프론트는 위치 보간
- 배포: 프론트 Vercel 등 / 서버 Railway·Render·AWS 등
- AI(LLM) 사용 없음

## 12. OKR (해커톤 기간 기준, 3안 중 택1)

> 전제: 해커톤 기간 중 한양대생 테스트 참가자 20명 내외를 모을 수 있다고 가정. 실거래 표본이 동별로 충분한지는 미확인.
> 참고 — 노스스타 지표 후보: **"자기 집(또는 관심 집)의 초과액을 확인한 한양대생 수"**. 아래 KR은 이 지표와 그 입력 지표를 겨냥한다.

### 안 1 — 「깨닫게 한다」(공감)
**Objective:** 해커톤 기간 안에, 한양대생이 3분 만에 "내가 월세를 얼마나 더 내고 있는지"를 숫자로 깨닫게 만든다.
- KR1: 테스트 한양대생의 **70% 이상**이 3분 안에 자기 집 또는 관심 집의 초과액 확인까지 도달
- KR2: 판정 결과를 본 참가자의 **70% 이상**이 "내 체감과 맞다/납득된다"고 응답
- KR3: 참가자의 **50% 이상**이 집을 1개 이상 찜하거나 청년안심주택 D-day 알림을 등록
- 근거: 아이디어 점수는 "문제를 사람들이 진짜 느끼는가"에서 갈린다. 실제 학생 반응 수치는 발표 신뢰도를 크게 올린다.

### 안 2 — 「믿을 수 있는 숫자」(기술 신뢰)
**Objective:** 적정 월세 계산을 심사위원이 믿을 수 있는 수준의 숫자로 만든다.
- KR1: 실거래 데이터 일부를 떼어 검증했을 때 적정 환산 월세 **오차 중앙값 15% 이하**
- KR2: 대상 5개 지역(행당·사근·마장·홍익·왕십리 등 동 단위) **모두에서 판정 가능한 표본(동별 30건 이상)** 확보 — "판정 보류" 비율 10% 이하
- KR3: 판정 API 응답 **p95 1초 이하**
- 근거: 기술 점수는 "계산했다"가 아니라 "얼마나 맞는지 측정했다"에서 나온다. 오차 그래프 한 장이 강력하다.

### 안 3 — 「같이 걷고 싶은 동네」(몰입·데모)
**Objective:** 3D 멀티플레이 동네가 2D 앱보다 집과 동네를 더 잘 이해하게 만든다는 것을 증명한다.
- KR1: 동시 접속 **20명**에서 중급 노트북 기준 **평균 30fps 이상** 유지
- KR2: 테스트 참가자의 3D 월드 **평균 체류 5분 이상**, 실내 입장 비율 60% 이상
- KR3: 실내 3D를 본 참가자의 **80% 이상**이 "평면도 이미지보다 공간이 잘 이해됐다"고 응답
- 근거: 3D·멀티플레이는 이 팀의 가장 큰 차별점이자 가장 큰 리스크. 성능과 몰입을 수치로 증명해야 "왜 3D냐"에 답할 수 있다.

> 세 안은 우열이 아니라 선택이다. 대회 심사 기준에서 가중치가 가장 큰 항목(아이디어 / 기술 / 완성도)에 맞춰 하나를 주 OKR로 고른다.
