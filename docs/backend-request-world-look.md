> **구현 완료** (`WorldService`: `look` 검증·중계, `state` 본인 제외, 최대 접속자 30). 계약서 6장에 반영함.

# 백엔드 요청: 멀티플레이 캐릭터 외형(`look`) 공유

프론트(캐릭터 꾸미기)는 준비됐다. 서버가 외형을 저장해 다른 접속자에게 전달만 해 주면 된다. `WorldService` 에 필드 하나와 메시지 하나를 추가하는 정도다.

## 외형 값

```json
{ "jacket": "school1", "hair": "#2a1d16", "skin": "#f2c9a5" }
```

- `jacket`: `school1` | `school2` | `school3` | `dept-is` (허용 목록에 없으면 버리고 기본 `school1`)
- `hair`, `skin`: `#rrggbb` (정규식 `^#[0-9a-fA-F]{6}$`, 아니면 기본값)
- 서버는 해석하지 않고 **검증 + 중계만** 한다. 잠바 종류는 프론트가 늘릴 수 있으니, 목록 검증 대신 "길이 ≤ 16인 영숫자·`-`" 정도로 느슨하게 해도 된다.

## 메시지

| 방향 | 메시지 | 설명 |
|---|---|---|
| 클라이언트 → 서버 | `{ "t": "look", "look": { jacket, hair, skin } }` | 접속 직후 1회 + 꾸밀 때마다. 잘못된 값은 조용히 버림 |
| 서버 → 클라이언트 | `{ "t": "look", "id": "...", "look": { ... } }` | 본인을 뺀 전원에게 중계 |
| 서버 → 클라이언트 | `welcome.players[]`, `join.player` 에 `look` 필드 추가 | 이미 접속해 있던 사람의 외형을 새로 온 사람이 바로 알 수 있게 |

`state`(10Hz)에는 `look` 을 넣지 않는다 (대역폭).

## 구현 메모

- `WorldPlayer` 에 `volatile String look`(또는 검증된 JSON 문자열) 하나 추가.
- `WorldService.onMessage` 의 `switch` 에 `case "look"` 추가. 속도 제한은 `emote` 처럼 400ms 간격이면 충분.
- `Pub` 레코드에 `look` 필드(`@JsonInclude(NON_NULL)` 이미 있음) 추가, `pub(p, true)` 일 때만 넣는다.
- 크기: 메시지 한도 2048바이트 안에 충분히 들어간다.

## 같이 고치면 좋은 것

1. **`state` 에서 본인 제외.** 지금은 본인에게도 자기 `state` 가 온다(확인: 접속자 A가 걸을 때 A도 `state` 를 받음). 프론트는 걸러내지만 대역폭이 낭비된다. 접속자가 늘수록 효과가 크다.
2. **최대 접속자 수.** 계약서 6장은 기본 50, 서버 `WorldProperties` 기본은 30. 시연이 30명이면 계약서 문구를 맞추면 된다.

## 프론트 동작 (참고)

- 받은 `look` 은 프론트가 한 번 더 검증한다(깨진 값은 기본 외형).
- `look` 이 없는 접속자는 기본 외형(`school1`)으로 그린다. 서버를 안 고쳐도 화면은 깨지지 않는다.
- 접속자가 어떤 외형이든 draw call 은 한 명당 7개로 같다.
