# 「찾았다. 내 돈을 다 써버린 놈이야」 — 주제 재해석 & 해커톤 OKR

> 대상: 대학생 / 형식: 개발 해커톤 / 목표: 아이디어성 + 기술성 + 데모 임팩트로 수상

---

## 0. 주제 해부: 이 문장에서 뭘 뽑아낼 수 있나

| 키워드 | 숨은 질문 | 재해석 여지 |
|---|---|---|
| **찾았다** | 무엇을 근거로 찾았나? | 탐지 · 추적 · 포렌식 · 추리 |
| **내 돈** | 돈이 정말 '돈'뿐인가? | 시간, 미래의 돈(할부), 남이 갚을 돈 |
| **다 써버린** | 왜 '나도 모르게' 사라졌나? | 무의식 소비, 자동결제, 조작된 소비 |
| **놈** | 범인이 누구인가? | 나 자신 · 구독 · 알고리즘 · 친구 · 사기꾼 · 물가 |

**핵심 인사이트:** 대부분의 팀은 "가계부 + 소비 분석 대시보드"로 갈 것이다. 차별점은 **'놈(범인)'을 누구로 정의하느냐**에서 나온다. 범인을 바꾸면 문제·데이터·기술이 전부 바뀐다.

---

## 1. 재해석 방향 6가지

### A. 범인은 「무의식의 나」 — 소비 트리거 포렌식
- **해석:** 돈을 쓴 건 나지만, *결정한 건* 피곤함·새벽 2시·시험기간·우울함이다. 범인은 "특정 상태의 나".
- **기능:** 결제 내역 × 컨텍스트(시간대, 수면, 캘린더 시험일정, 날씨, 위치)를 결합해 "범행 패턴" 도출 → **범인 몽타주** 카드("시험 D-3, 새벽 1시, 배달앱을 여는 너") → 위험 시간대 직전 개입 알림.
- **기술 포인트:** 시계열 이상탐지, 컨텍스트 피처 엔지니어링, 간단한 인과추론(시험기간 vs 비시험기간 비교), LLM 기반 '수사 보고서' 생성.
- **수상 포인트:** "돈 관리 = 자기 이해"로 철학적 깊이. 몽타주라는 바이럴 가능한 결과물.

### B. 범인은 「숨은 구독 & 다크패턴」 — 유령결제 수배
- **해석:** 무료체험 후 자동결제, 해지 어렵게 만든 UI. 범인은 서비스 설계 그 자체.
- **기능:** 거래내역에서 주기성 결제 자동 탐지 → "유령 구독 수배 전단" → 해지 페이지 딥링크/해지 절차 가이드 자동 생성. 브라우저 확장으로 결제 페이지 다크패턴(사전 체크된 동의, 숨겨진 자동갱신) 실시간 경고.
- **기술 포인트:** 주기 탐지 알고리즘(FFT/간격 클러스터링), 가맹점명 정규화, DOM 분석 + LLM으로 다크패턴 분류, 약관 요약.
- **수상 포인트:** 사회적 메시지(소비자 보호) + 크롬 확장 라이브 데모가 강력.

### C. 범인은 「친구들」 — N빵 미정산 추적기
- **해석:** 내 돈은 사라진 게 아니라 친구들 지갑에 흩어져 있다. MT, 팀플 회식, 택시 N빵.
- **기능:** 단톡 대화 + 송금 내역을 매칭해 "누가 아직 안 보냈는지" 자동 추적 → 최소 송금 횟수로 정산 경로 계산 → 귀엽고 덜 민망한 독촉 메시지 생성.
- **기술 포인트:** 대화 텍스트에서 금액·참여자 추출(NER/LLM), 그래프 기반 최소 현금흐름(min cash flow) 알고리즘, 송금-정산 매칭.
- **수상 포인트:** 대학생 공감도 최상. 심사위원도 웃는 데모. 단, 기존 정산앱(토스 등)과 차별화 설명 필요 → "대화에서 자동으로 장부가 생긴다"가 차별점.

### D. 범인은 「알고리즘」 — 피드가 내 돈을 썼다
- **해석:** 인스타·유튜브 숏폼 광고가 나를 조종했다. 범인은 추천 시스템.
- **기능:** 브라우저 확장/스크린 로그로 광고·상품 노출 기록 → 실제 구매와 연결(attribution) → "이 구매는 노출 3회 뒤 일어남, 범인: ○○ 숏폼 광고" → 노출 다이어트 모드.
- **기술 포인트:** 노출 이벤트 수집, 상품 이미지/텍스트 임베딩 유사도 매칭, 마케팅 attribution 모델을 개인 단위로 역적용.
- **수상 포인트:** "기업이 쓰는 기술을 소비자가 역이용"이라는 반전 서사. 기술 난이도 높음(리스크도 높음).

### E. 범인은 「과거의 나」 — 할부·BNPL 시간여행 수사
- **해석:** 이번 달 내 돈을 쓴 건 3개월 전의 나다. 할부·후불결제가 미래의 나에게 청구서를 보낸다.
- **기능:** 할부/후불 내역을 타임라인으로 시각화 → "미래의 나에게서 빼앗은 돈" 미리보기 → 결제 직전 "미래의 나" 캐릭터가 말을 거는 개입(LLM 페르소나).
- **기술 포인트:** 현금흐름 시뮬레이션, 미래 잔고 예측, 페르소나 대화.
- **수상 포인트:** 감성 + 스토리텔링이 강하고 발표 오프닝이 좋다. 기술성은 A·B보다 약할 수 있음 → 예측 모델로 보완.

### F. 범인은 「진짜 범인」 — 대학생 대상 금융사기 추적
- **해석:** 말 그대로 내 돈을 가져간 놈. 중고거래 사기, 스미싱, 자취방 보증금 사기.
- **기능:** 중고거래 채팅/링크/계좌번호 붙여넣기 → 사기 위험 스코어링 + 근거 하이라이트 → 피해 시 신고용 증거 패키지 자동 생성.
- **기술 포인트:** URL/텍스트 피싱 분류, 사기 수법 패턴 매칭, 공개 사기계좌 조회 연동, 증거 타임라인 자동화.
- **수상 포인트:** 사회적 임팩트 최상, 공공/금융기관 심사위원에게 강함. 재미 요소는 약함 → 추리 UX로 보완.

## 2. 비교 평가 (5점 만점, 주관적 추정)

| 방향 | 아이디어 참신성 | 기술성 | 데모 임팩트 | 대학생 공감 | 구현 리스크(낮을수록 좋음) |
|---|---|---|---|---|---|
| A. 무의식의 나 | 5 | 4 | 4 | 5 | 중 |
| B. 유령 구독/다크패턴 | 4 | 4 | 5 | 4 | 중 |
| C. 친구 N빵 | 3 | 3 | 5 | 5 | 낮음 |
| D. 알고리즘 | 5 | 5 | 4 | 4 | **높음** |
| E. 과거의 나 | 4 | 3 | 4 | 4 | 낮음 |
| F. 진짜 사기꾼 | 3 | 4 | 3 | 3 | 중 |

### 추천 조합: **「수사본부」 컨셉 = A를 메인, B·C를 '용의자'로 편입**
앱 하나가 *수사 게임*처럼 동작한다. 내역을 올리면 **용의자 라인업**이 뜬다.
- 용의자 1: 새벽 2시의 나 (A)
- 용의자 2: 유령 구독 (B)
- 용의자 3: 정산 안 한 친구들 (C)

각 용의자마다 증거(거래·패턴)와 "범행 기여액"이 붙고, 마지막에 **"진범은 ○○"** 판결 리포트가 나온다.
→ 주제 문장을 그대로 UX로 구현해 심사위원 기억에 남고, 탐지 모듈이 여러 개라 기술 설명도 풍부하다. 시간이 부족하면 C를 빼면 된다.

## 3. 해커톤 팀 OKR (3안)

> 해커톤 맥락에 맞게 OKR 기간 = 대회 준비~본선. KR은 "기능 몇 개 만들기"가 아닌 **결과(심사/사용자 반응)** 중심.

### OKR 1 — 「공감」 중심
**Objective:** 심사위원과 대학생 모두가 "이거 내 얘기다"라고 느끼는 서비스를 증명한다.
- KR1: 사전 테스트 대학생 20명 중 70% 이상이 자기 "범인 리포트"를 *정확하다*고 평가
- KR2: 테스트 참여자의 50% 이상이 결과 카드를 자발적으로 공유(스크린샷/링크)
- KR3: 발표 Q&A에서 "차별점이 뭐냐" 류 질문 0~1회 이하 (= 컨셉이 첫 1분에 전달됨)
- **근거:** 해커톤 아이디어 점수는 공감·명확성에서 갈린다. 실제 사용자 반응 숫자는 발표 신뢰도를 크게 올린다.

### OKR 2 — 「기술 신뢰」 중심
**Objective:** "진짜로 찾아낸다"는 걸 숫자로 보여주는 탐지 엔진을 만든다.
- KR1: 라벨링한 테스트셋에서 정기결제(유령 구독) 탐지 정밀도 ≥ 90%, 재현율 ≥ 80%
- KR2: 소비 트리거 분석이 비트리거 구간 대비 유의미한 지출 차이(예: +30% 이상)를 최소 3개 패턴에서 검출
- KR3: 거래 500건 업로드 → 리포트 생성까지 10초 이내
- **근거:** 기술성 점수는 "AI 붙였다"가 아니라 "성능을 측정했다"에서 나온다. 정밀도/재현율 슬라이드 한 장이 강력하다.

### OKR 3 — 「행동 변화」 중심
**Objective:** 범인을 찾는 데서 끝나지 않고, 범행을 *막는* 서비스임을 보여준다.
- KR1: 1주일 파일럿 참여자의 트리거 시간대 지출이 기준 주 대비 20% 이상 감소
- KR2: 개입 알림을 받은 사용자의 40% 이상이 "결제 보류/취소" 선택
- KR3: 파일럿 참여자 중 유령 구독 1건 이상 실제 해지 비율 ≥ 30%
- **근거:** "분석 대시보드"와 "행동을 바꾸는 제품"의 차이를 증명. 시간이 있으면 가장 강한 스토리, 없으면 가장 달성 어렵다.

> 세 안은 우열이 아니라 선택이다. 대회 심사 기준표에서 가중치가 가장 높은 항목에 맞춰 1개를 주 OKR로 고르는 것을 권장.

## 4. 가정 & 데이터 리스크 (꼭 확인)

1. **실제 금융 데이터 접근:** 마이데이터 API는 해커톤에서 사실상 사용 어려움. 대안 → 은행/카드앱 **CSV·엑셀 내보내기 업로드**, **결제 알림 문자 파싱**, 영수증 OCR, 그리고 데모용 **합성 데이터**(대학생 페르소나 3명 분량) 준비.
2. **개인정보:** 실데이터 테스트 시 동의서 + 로컬 처리/익명화를 발표에서 언급하면 감점 방어 가능.
3. **단톡 데이터(C안):** 카카오톡 대화 내보내기(.txt) 파일 업로드 방식이 현실적.
4. **심사 기준 미확인:** 대회 공식 심사 항목(아이디어/기술/완성도/사업성 비율)을 확인 후 OKR 1개 선택 필요.

## 5. 레퍼런스 조사: 이미 있는 것과 빈자리

| 구분 | 사례 | 핵심 | 시사점 |
|---|---|---|---|
| 일반 가계부 | 모두의 가계부, 무소비가계부, 두나 가계부, 텅장 세이버 | 입력 간소화, 예산 안에서만 기록, 하루 사용 가능액 | **기록·예산 앱은 포화 상태.** "가계부"로 가면 바로 비교당한다 |
| 공유 가계부 | 가계부부 | 커플·부부 공동 장부 | 룸메·팀플·동아리 단위로 확장할 여지 |
| 캠퍼스 금융 플랫폼 | 신한 헤이영 캠퍼스 (약 100개 대학) | 모바일 학생증·출결·학사 + 계좌·간편결제·이름/학과 송금 | 은행이 이미 '학사+금융'을 묶었다 → **학사 일정(시험기간)과 소비를 엮는 분석**은 아직 비어 있다 |
| 시간 환산 | 아 오늘 얼마 벌었지?(아오얼) | 연봉 → 초 단위 수입, 소비를 노동시간으로 환산 | 직장인 대상. **알바 시급 기반 대학생 버전은 없다** |
| 해외 학생 프로젝트 | UW HuskyBank, SpendX, Mabu(2026 논문) | 게이미피케이션, 아바타 보상 | 게임화는 흔하다. **'추리/수사' 메타포는 보이지 않는다** |
| 해커톤 | HuskyHack, Stanford "재미있게 저축하기", 美 재무부 MyMoneyAppUp(소비 만족도 추적 앱 수상) | 대학생 재무 도구 | "얼마 썼나"보다 **"쓴 게 만족스러웠나"** 축이 수상한 전례 있음 |

**트렌드 신호:** 외식 물가 상승(서울 칼국수 평균 1만원 돌파), 천원의 아침밥 확대, 디지털 구독료 비중 증가, 무지출·노바이(No Buy) 챌린지, "일상 지출은 줄이고 나를 위한 작은 사치는 한다".

**빈자리 요약:** ① 대학생 *맥락*(학사일정·알바·자취)과 결합한 분석 ② 소비를 '양'이 아닌 '만족/후회'로 보는 시각 ③ 돈 이외의 자원 ④ 안 써서 잃은 돈 ⑤ 수사/추리 UX.

## 6. 「쓰다」를 다시 읽기 — 단어 하나에서 방향 7개 더

"쓰다"는 한국어에서 뜻이 아주 많다. 그리고 **"내 돈"**도 꼭 지갑 속 현금일 필요가 없다.

| # | 「쓰다」의 의미 | 재해석된 문장 | 서비스 방향 | 기술 포인트 |
|---|---|---|---|---|
| **G** | 쓰다 (맛이 쓰다) | "내 돈을 **쓰게** 만든 놈" = 후회만 남긴 소비 | **소비 맛 지도**: 결제 직후·3일 뒤·한 달 뒤 만족도를 짧게 묻고, 단 소비/쓴 소비를 분류. 범인은 "쓴맛 패턴" | 지연 피드백 수집, 후회 예측 모델(결제 시점 피처로 후회 확률 예측) |
| **H** | 마음·신경·애·시간을 쓰다 | "내 **[시간·집중력·체력]**을 다 써버린 놈" | **인생 자원 가계부**: 돈 대신 시간·주의력을 같은 장부에. 스크린타임, 통학, 알바 시간을 '지출'로 기록 | OS 스크린타임/캘린더 연동, 자원 간 환산 모델 |
| **I** | 돈을 쓰다 = 노동시간을 쓰다 | "이 치킨은 편의점 알바 **2시간 10분**" | **알바 시급 환율**: 모든 지출을 내 시급 기준 노동시간으로 환산하고, 결제 직전에 보여줌 (아오얼의 대학생 버전) | 알바 근무기록 + 지출 매칭, 실시간 환산 위젯 |
| **J** | 누명을 쓰다 | "범인으로 몰린 놈은 **억울하다**" | **억울한 지출 변호사**: 낭비라고 몰린 지출 중 실제로는 물가 상승 탓인 부분을 분리. "너는 덜 먹었는데 더 냈다" — 개인 물가지수 | 품목별 물가지수(통계청 공공데이터)와 내 지출 매칭, 개인 인플레이션 계산 |
| **K** | (안) 쓰다 → 사라짐 | "내가 **안 써서** 날아간 돈" | **사라진 돈 수색대**: 만료된 기프티콘, 소멸 포인트, 안 받은 장학금·청년지원금, 놓친 학생할인, 휴면계좌 | 기프티콘 OCR + 만료 알림, 청년정책 공공 API 매칭, 혜택 추천 |
| **L** | 내 돈을 **남이** 쓰다 (집단의 돈) | "내 **등록금·학생회비**를 다 써버린 놈" | **등록금 영수증**: 대학 결산 공시 데이터로 "내가 낸 등록금 1원이 어디 갔는지" 개인화 영수증 생성. 학생회비 투명 장부 | 대학알리미 공시 데이터 크롤링/정제, 비율 배분 시각화, (선택) 변경 불가 장부 |
| **M** | 쓰다 (글을 쓰다) | "내 돈 이야기를 **다 써(기록해)** 간 놈" | **내 소비 데이터 추적기**: 결제할 때마다 내 구매 기록이 어느 회사로 넘어가는지(카드사·PG·광고 SDK) 추적. 범인은 데이터를 '쓰는' 기업 | 앱/웹 트래커 탐지, 개인정보 처리방침 LLM 분석, 데이터 흐름 그래프 |

### 이 중에서 눈여겨볼 것

- **K. 사라진 돈 수색대**가 가장 반전이 강하다. 주제가 "돈을 쓴 놈"인데 답이 "**안 쓴 나**"다. 발표 첫 장에서 심사위원 머리에 남고, 실제로 돈을 '찾아주는' 결과가 나와서 데모 임팩트가 크다. 공공 API(청년정책 등)를 쓰기 때문에 기술성 설명도 된다.
- **L. 등록금 영수증**은 대학생만 공감할 수 있는 주제이고, 공공데이터를 개인화하는 기술성과 사회적 메시지를 모두 갖췄다. 데이터 정제 난이도는 확인이 필요하다.
- **G + I**는 기존 가계부와 **측정 단위**부터 다르다(금액 → 후회도, 금액 → 노동시간). 앞의 방향 A(수사본부)에 '증거' 모듈로 붙이기 좋다.

### 업데이트된 추천: 「수사본부 v2」
**용의자를 '쓰다'의 여러 뜻으로 구성한다.**
- 쓴 놈 (A, 무의식의 나) → *범행 시간대·트리거*
- 쓰게 만든 놈 (G, 후회 소비) → *쓴맛 증거*
- 안 써서 날린 놈 (K, 사라진 돈) → *반전 용의자*
- 누명 쓴 놈 (J, 물가) → *무죄 석방*

발표 구조: "범인을 찾으러 갔더니, 쓴 놈·쓰게 만든 놈·안 쓴 놈·누명 쓴 놈이 있었다." → '쓰다'라는 단어를 끝까지 판 해석이라 주제 해석 점수에서 유리하다.

### 해석이 한층 깊어지는 지점
한양대로 좁히니 "범인 = 나"라는 자기반성 서사 외에 **"범인 = 구조"** 서사가 생긴다.
- 월세·관리비·등록금은 내가 통제할 수 없는 돈이다. 이 경우 **"나는 범인이 아니었다"**를 증명해 주는 것 자체가 가치가 된다(J).
- 등록금·학생회비는 **"내 돈을 남이 쓴다"**는 구조다. 범인을 잡는 게 아니라 **감시할 수 있게** 해 주는 쪽으로 간다(L).

→ 발표 서사 후보: **"범인을 찾았다. 반은 나였고, 반은 내가 아니었다."**

### 아직 모르는 것 (팀이 직접 확인하면 좋은 것)
1. 한양대 학식 가격 변화 — 검색으로는 확인 못 함. 생협/학생식당 공지 확인 필요
2. 한양대 교내 장학금 종류와 미신청률 — 학교 장학 공지 확인 필요
3. 에브리타임 한양대 게시판의 돈 관련 불만 (정산, 월세, 관리비, 회비) — 로그인이 필요해 직접 볼 수 없음. **팀원이 키워드 검색 후 사례 10개만 모아도 발표 근거로 충분**
4. 간단한 설문(한양대생 30명 내외): "이번 달 돈이 어디 갔는지 아는가 / 받을 수 있었는데 못 받은 돈이 있는가 / 회비 사용처를 아는가"

## 8. 후보 아이디어: 한양대 자취방 추천 + 3D 집 투어 + 과 건물 도보 경로

### 팀 아이디어 요약
- 다방·직방처럼 집을 보여주되 **한양대 전용**
- 추천된 집은 **3D로 들어가 볼 수 있음** (메타버스 느낌)
- **전공 입력 → 내 과 건물 등록** → 집에서 정문·후문 등 **여러 입구 중 최적 입구를 거친 도보 경로** 기준으로 가까운 집 추천

### 8-1. 실제 도면 확보 가능성 — 결론: **실제 평면도를 대량으로 구하는 건 불가에 가깝다**

| 경로 | 가능 여부 | 메모 |
|---|---|---|
| 건축물대장 평면도 (세움터) | ❌ 사실상 불가 | 평면도는 원칙적으로 **소유자·이해관계인만** 발급, 증빙 필요. 남의 원룸 도면은 못 뗀다 |
| 건축HUB 건축물대장 API (공공데이터포털) | ⭕ 부분 가능 | 도면은 없지만 **호별 전유면적·층·호 위치**는 누구나 조회 가능 |
| 다방·직방 매물 데이터 | ❌ 위험 | 공식 API 없음, 크롤링은 약관·저작권 리스크 |
| 국토부 전월세 실거래가 API | ⭕ 가능 | 오피스텔 전월세 확인됨 (연립다세대는 포털에서 재확인 필요). 보증금·월세·면적·건물·계약월. 단, *과거 계약*이지 현재 매물은 아님 |

**실제 확인 (2026-11-07):** 한양대 인근 원룸텔(서울 성동구 행당동 16-53, 다방 계열 고방 등록 매물)로 세움터에서 열람을 시도했다. 건축물대장 발급 화면은 **회원 로그인** 또는 **비회원 개인정보 동의·입력**을 요구해서 그 앞에서 멈췄다. 평면도(건축물현황도)는 여기에 더해 소유자·이해관계인 증빙이 필요하다.
→ 현실적인 경로: **팀원 본인이 세입자인 자취방**은 임대차계약서로 이해관계인 증빙이 가능할 수 있다. 팀원 집 도면은 직접 받아 보고, 나머지는 스캔·면적 기반 생성으로 간다.
→ 덤: 이 매물은 "한양대 도보 1분"에 11~14㎡ 원룸이 **월 95~110만 원**으로 올라와 있다. 같은 페이지의 "근처 다른 방"은 월 31~48만 원. **'바가지 혐의' 데모 사례로 쓸 만하다.**

### 8-2. 그래서 3D는 이렇게 만든다 (3단 조합 추천)

| 방식 | 방법 | 장점 | 한계 | 역할 |
|---|---|---|---|---|
| **① 직접 스캔** | 팀원·지인 자취방을 iPhone LiDAR(Apple **RoomPlan** → USDZ) 또는 **Gaussian Splatting**(Polycam·Scaniverse·Luma 등 → 웹 뷰어)로 촬영 | 실사 수준, 데모 임팩트 최강 | 수량 한계(5~10채) | **데모 주인공 집** |
| **② 면적 기반 자동 생성** | 건축HUB 전유면적 + 원룸 유형 템플릿(일자형·분리형·1.5룸·복층) → three.js로 절차적 생성 | 모든 건물에 적용 가능, 기술성 설명 쉬움 | "추정 레이아웃"임을 명시해야 함 | **커버리지** |
| **③ 평면 이미지 → 3D (스트레치)** | 매물 사진·손그림 평면도를 CubiCasa5k 계열 모델로 벽·문 인식 → 벡터화 → 3D 압출 | AI 기술성 어필 | 한국 원룸 도면 정확도 미검증, 오래된 의존성 | **시간 남으면** |

> 참고: 직방은 이미 360° 파노라마 **VR 홈투어**, 네이버페이 부동산도 **VR 매물투어(치수 측정)**를 한다. "3D로 집을 본다" 자체는 차별점이 아니다. 차별점은 **왜 3D로 보는가**에서 나와야 한다.

### 8-3. 도보 경로 — 여기가 진짜 차별점
- 학교 밖: **TMAP 보행자 경로 API**로 집 → 각 입구까지 경로·시간 (보도 아닌 차도로 안내되는 경우가 있다는 지적 있음 → 검증 필요)
- 학교 안: 상용 지도 API는 캠퍼스 내부 길을 잘 모른다. **입구 → 과 건물 캠퍼스 그래프를 팀이 직접 구축**(OSM 데이터 + 직접 보정) → 한양대 전용 데이터 자산 = 기술성 + 다방·직방이 못 하는 영역
- 추가 아이디어: **고저차 보정**(언덕·계단은 같은 거리라도 더 오래 걸림), **시간표 연동**(내 수업 건물이 요일마다 다르면 주간 총 통학 시간 계산)

### 8-4. 솔직한 평가

**좋은 점**
- 앞에서 찾은 근거(한양대 인근 월세 +11.3%, 관리비 +42%)와 바로 연결된다
- 한양대생이면 누구나 공감, 데모에서 "내 과 건물 입력"하는 순간이 강렬하다
- 공공데이터 + 경로 그래프 + 3D라는 기술 스택이 해커톤 심사에서 설명하기 좋다

**위험한 점**
1. **주제 연결이 약해질 수 있다.** 그대로 두면 "다방 한양대 버전 + 3D"로 보이고, "찾았다. 내 돈을 다 써버린 놈"이 어디 있냐는 질문을 받는다.
2. **"왜 3D(메타버스)?"** 질문에 답이 필요하다. 이미 VR 투어는 있다.
3. **범위가 넓다.** 추천 + 3D + 경로 + 시세를 해커톤 기간에 다 하면 전부 얕아진다.

### 8-5. 주제와 묶는 방법 — **「계약하기 전에 잡는다」**

> 원문은 "다 써버린 놈"(과거형). 자취방은 **계약하는 순간 2년치 돈이 묶인다.** 써버린 뒤에 찾으면 늦다 → **"내 돈을 다 써버릴 놈을, 계약 전에 찾아낸다."**

각 집을 **용의자**로 보고 "진짜 비용"을 수사한다:

| 증거 | 내용 | 데이터 |
|---|---|---|
| **바가지 혐의** | 같은 동네·비슷한 면적 실거래 대비 월세가 얼마나 비싼가 | 전월세 실거래가 API + 건축HUB 면적 |
| **숨은 관리비 혐의** | 관리비 포함 실제 월 지출, 동네 평균 대비 | 매물 입력값 + (월 10만원 이상 정액관리비는 세부 표시 의무, 2023.9 시행) |
| **시간 도둑 혐의** | 집 → 입구 → 과 건물 도보 시간 × 주간 등교 횟수 → **알바 시급으로 환산한 월 비용** | TMAP + 캠퍼스 그래프 + 시간표 |
| **공간 사기 혐의** | 사진은 넓어 보였는데 실제로 내 침대·책상이 들어가나 | 3D 모델 + 가구 배치 |

→ 최종 화면: **"표시 월세 55만 원, 진짜 월세 81만 원. 범인: 언덕길(월 14만 원)과 관리비(12만 원)."**

**3D의 역할도 여기서 정해진다:** 구경용 메타버스가 아니라 **"공간 사기 혐의"를 검증하는 도구**다. 내 가구를 넣어 보고, 집 → 과 건물 등굣길을 3D로 미리 걸어 본다. 이렇게 하면 "왜 3D?"에 답할 수 있다.

### 8-7. 추정 평면도 정확도를 올리는 단서들

배치도 실물 확인(구의동 다가구 예시): 건물 외곽 치수, 기둥 그리드(X1~X4, Y1~Y4 간격), 주출입구 위치, 방위(북쪽 화살표), 접한 도로 폭(4M/6M), 정북 일조사선이 나온다.

| 단서 | 어디서 | 평면 추정에 주는 정보 |
|---|---|---|
| 외곽 치수 + 그리드 간격 | 배치도 | 건물 윤곽 = 평면 생성의 경계. 그리드 간격이 벽 위치 후보 |
| 주출입구 위치 | 배치도 | 계단실(코어) 위치 → 나머지 공간을 세대로 분할 |
| 방위 + 일조사선 | 배치도 | 창문 방향, 상층부 셋백(꼭대기 층 방이 작아지는 이유) |
| 층수, 층별 면적·용도, 가구수, 구조, 사용승인일 | 건축물대장 표제부·층별개요 API | 층당 세대 수 → 세대당 면적, 건축 연도별 전형 평면 |
| 계약 면적 | 단독/다가구·연립다세대 전월세 실거래가 API | 실제 세대 면적 분포 |
| 방 구조(오픈형/분리형/1.5룸), 방향 | 매물 정보 (사용자 입력) | 템플릿 유형 선택 |
| 외벽 창문 배치, 실외기·가스계량기·우편함 개수 | 로드뷰 사진 | 층당 세대 수와 세대 경계 검증 |
| 실제 거주자 스케치·스캔 | 사용자 크라우드소싱 | 다가구는 층마다 평면이 반복되는 경우가 많아 한 집이 같은 건물 다른 층의 근거가 된다 |

**생성 방식:** 데이터셋에서 고르기(검색)에 더해, 건물 윤곽 + 방 구성을 넣으면 평면을 생성하는 연구 모델(Graph2Plan, House-GAN++, HouseDiffusion 계열)을 쓰거나, 규칙 기반 분할(코어 배치 → 세대 분할 → 욕실·현관 배치)로 생성.
**표시:** 단서가 많을수록 높은 **추정 신뢰도**를 화면에 함께 보여준다.

### 8-8. 청년주택(공공임대) 평면도 — **공개되어 있다**

- 서울시 청년안심주택(역세권 청년주택)·LH 행복주택은 모집공고와 함께 **전자팸플릿/홈페이지에 주택형별 단위세대 평면도**를 게시한다. 공고문 원문에 "평면도는 전자팸플릿을 통해 확인", "단위세대 평면도는 개략적 이해를 돕기 위한 것", "동·호수에 따라 좌우 대칭될 수 있음"이라고 명시되어 있다 (2023년 3차 청년안심주택 공고문, 구의동 587-64 역세권 청년주택 공고문에서 확인).
- 공고문 표에 주택형(예: 16형 = 대학생·청년, 26형, 32A/32B)별 **전용·공용면적**이 함께 나온다.
- 한양대 주변 사례: **왕십리역 청아진** (성동구 홍익동 150 외, 133세대), **라봄성동** (마장동 일대, 181세대). 단지 정보는 공고 원문으로 재확인 필요.

**활용**
1. **템플릿 라이브러리:** 서울 청년주택 16~26㎡ 평면도를 모아 추정 평면도 템플릿으로 쓴다. 해외 데이터셋보다 한국 원룸 구조에 훨씬 가깝다.
2. **진짜 3D 집:** 공개된 실제 평면도라 그대로 3D로 세울 수 있다 → 데모에서 "들어가 보기" 가능한 실제 집.
3. **대안 제시:** "이 원룸은 바가지 혐의, 근처 청년안심주택은 같은 면적에 ○○만 원" → 범인을 찾은 뒤 **탈출구**까지 보여준다.

※ 주의: 팸플릿 평면도는 "개략적"이라 실제와 차이가 있을 수 있고, 이미지 저작권·이용 조건은 확인 필요.

### 8-6. 해커톤 범위 제안
- **꼭:** 과 건물 입력 → 입구별 도보 경로 → 진짜 월세 계산 → 용의자 리포트
- **데모 하이라이트:** 직접 스캔한 실제 자취방 3~5채 3D 투어 + 가구 배치
- **있으면 좋음:** 면적 기반 자동 3D, 고저차 보정, 시간표 연동
- **버림:** 실시간 매물 중개, 평면 이미지 AI 인식

## 9. 기술 스택

### 9-1. 레퍼런스: 산사(sansatemple.com) 실제 분석 (2026-11-07, 브라우저에서 번들·네트워크 확인)

| 영역 | 확인된 것 |
|---|---|
| 렌더링 | **Three.js r180** (`window.__THREE__ = "180"`), WebGL2 캔버스 1개. React 등 UI 프레임워크 흔적 없음 → 바닐라 Three.js로 보임 |
| 빌드 | **Vite** (해시 붙은 청크: `index-*.js`, `game-*.js` 약 1.4MB) |
| 3D 에셋 | **GLB** (스님 캐릭터, 불상, 고양이 등) + **Draco·KTX2·Meshopt** 압축 로더. 나무 등은 **InstancedMesh** |
| 환경 | 번들에 `Sky`, `Water`, `CSM`(그림자 분할로 추정) 문자열 → three.js 예제 모듈 사용으로 추정 |
| 멀티플레이 | 네이티브 **WebSocket** → `/presence` 엔드포인트가 **Cloudflare Workers**에 있음. URL의 `room=maru-02&instance=0&region=apac`, 화면의 "50/50·서버가 가득 찼어요" → 방/인스턴스 단위 정원 50명. presence 처리는 **Web Worker**로 분리 |
| 기타 | 번들에 `supabase` 문자열(데이터·인증 용도로 추정), Cloudflare 호스팅·분석, GA4 |

→ 요약: **Vite + 바닐라 Three.js + 압축 GLB + Cloudflare Workers WebSocket**. 해커톤 팀도 충분히 따라 할 수 있는 구성이다.

### 9-2. 우리 서비스 추천 스택

| 영역 | 추천 | 이유 / 대안 |
|---|---|---|
| 프론트 | **Vite + React + TypeScript** | 왼쪽 메뉴바·검색·필터 같은 UI가 많아서 React가 편하다 |
| 3D | **React Three Fiber + drei** (Three.js) | UI와 3D를 같이 다루기 쉽다. 산사처럼 바닐라 Three.js도 가능 |
| 캐릭터 이동 | **@react-three/rapier** (물리) + **ecctrl** (3인칭 컨트롤러) + 모바일은 가상 조이스틱 | 직접 만들면 충돌 처리에서 시간을 많이 쓴다 |
| 동네 3D | **OSM 또는 국가 GIS 건물 데이터** → 건물 윤곽을 높이만큼 **압출**한 로우폴리 건물. 지형은 DEM(고도)로 언덕 표현 | 실사 대신 산사처럼 **스타일라이즈드**로 가면 예쁘고 가볍다. 범위는 한양대 반경 약 1km로 제한 |
| 2D 지도 모드 | **카카오맵 JS SDK** (또는 MapLibre + OSM) | 다방처럼 지도에서 검색 → 클릭하면 3D로 "입장". 위경도 ↔ 3D 좌표를 같은 변환으로 맞춘다 |
| 집 내부 | ① 평면도 → 벽·문 JSON → 코드로 벽 압출 ② 직접 스캔 GLB(Polycam 등) ③ (선택) Gaussian Splat 뷰어 | 문 앞에 가면 실내 씬을 지연 로딩해서 전환 |
| 에셋 | Blender + **gltf-transform**으로 Draco/KTX2 압축 | 산사와 같은 방식, 모바일 로딩 시간 확보 |
| 경로 | 학교 밖: **TMAP 보행자 API**, 학교 안: **입구·건물 노드 그래프 직접 구축 + A\*** | 3D 월드 위에 등굣길 라인 표시, 고저차 가중치 |
| 데이터·백엔드 | **Supabase (Postgres + PostGIS)** | 매물·청년주택·평면도·사용자 등록 집 저장, 위치 검색 |
| 데이터 수집 | 건축물대장 API, 전월세 실거래가 API, 청년주택 공고(수동 + 크롤링) | 공고 요약·자격 진단에는 LLM(Claude API) |
| 멀티플레이 (선택) | Supabase Realtime 또는 Cloudflare Workers(Durable Objects) WebSocket | "친구랑 같이 집 보러 가기" — 있으면 데모가 화려하지만 필수는 아님 |
| 배포 | Vercel 또는 Cloudflare Pages | |

### 9-3. 화면 구조 (3가지 진입 방식)
1. **걸어서:** 한양대 정문에서 시작 → 캐릭터로 동네를 걸으며 건물 위 말풍선(월세, 바가지 혐의) 확인 → 문으로 들어가 실내 보기
2. **메뉴바에서:** 왼쪽 목록(가격·도보 시간·청년주택 여부 필터) → 클릭하면 그 집 앞으로 순간이동
3. **지도에서:** 2D 지도 검색 → 핀 클릭 → 3D 입장

### 9-4. 리스크
- 동네 전체를 3D로 만드는 작업량 → 데이터 자동 압출 + 주요 건물 몇 개만 수작업
- 모바일 성능 → 로우폴리, 인스턴싱, 압축 텍스처, 실내는 지연 로딩
- 멀티플레이는 마지막에 붙이거나 생략
